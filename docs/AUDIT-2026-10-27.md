# Workflow audit ? 27 October 2026

## Corrected in this release
- Prepared classroom navigation returns to its teaching-session lobby, not the older join-first room creator.
- Removed the competing legacy classroom link from teaching-session selection. Existing data is retained.
- Finished classrooms hide message, draft, position and facilitator mutation controls; saved reports remain available.
- Unchanged lobby snapshots no longer rebuild buttons every polling interval; stale replies from before a navigation or action are ignored.
- Approval lists retain their controls when unchanged and ignore replies belonging to an earlier screen.
- Saving a prepared classroom clears the previous roster from the next creation form.
- Missing-function errors distinguish teaching-session setup from the end-session migration.
- Account wording distinguishes session deletion and saved live work from unsaved solo progress.
- Supplementary SQL rejects approval after a session ends and retains the ended-room write guard.

## Required database deployment
Apply `supabase/audit-session-guards.sql` in the existing Supabase project's SQL Editor. It replaces functions; it does not delete classroom data. Browser publication alone does not apply database migrations.

## Verified by automated tests
Authentication gate, professor permissions, private role visibility, classroom isolation, prepared name/code approval, individual role assignment, report version conflicts, facilitator stage timing, and ended-session write rejection. These are local database and application tests, not a production multi-device acceptance trial.

## Remaining gaps ? do not describe as complete
- Integrated video, audio and screen sharing are not implemented. Shared audible/visible prebrief across remote universities cannot yet be delivered by this release.
- No live AI model is connected; scripted practice is not a live AI delegate.
- Prepared rosters have no editing/recovery workflow for a lost student browser session.
- Approval polling should be scoped to the current room request rather than all historical requests.
- Editable Word export is not yet available for the shared classroom report.
- Full browser visual review and a professor plus four independent student-device acceptance trial remain necessary.
- Legacy classroom implementation remains for existing records, although removed from the prepared-session navigation.

## Acceptance trial before classroom use
Use a disposable session. Prepare two rooms with different names and roles. Join each from independent browser profiles; approve only matched names. Verify own brief visibility, other-room denial, messages and events, all four timed stages (10/20/15/15 minutes), report save/download, and early end from a paused timer. Do not use or end an existing teaching session for testing.
